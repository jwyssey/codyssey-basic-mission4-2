# 검증 결과와 범위

2026-09-18 실제 제공 바이너리의 비교 실행 및 수집기 검증 완료.

이 문서는 당시 WSL 제출 증거의 검증 기록이다. Docker 구성 추가 후의 테스트와 실제 컨테이너 실험은 [Docker 검증 기록](DOCKER-VERIFICATION.md)을 참고한다.

## 실제 앱: 검사 50개 통과

[실행 결과 원문](../evidence/verification.txt)은 `python3 scripts/verify-evidence.py`로 확인한다.

- 동일 원본 SHA256, 일반 계정 UID 1000, 부팅 검사·READY 확인
- 최종 비교 6회의 환경변수와 단일 변수 변경, 동일 관찰 시간·샘플 간격 확인
- 실제 포트 소유 워커, 시계열·스레드 관측, 시스템 도구 접근 성공 확인
- OOM 두 번의 RSS 증가, MemoryGuard 로그, 수집기 신호 없는 -9 종료와 생존 연장
- CPU 상승, Watchdog 원문, 수집기 신호 없는 -15 종료와 After 생존
- 양방향 락 획득·대기, PID 생존, 자원·로그의 79.317초 정체
- CPU/Deadlock After에서 90초 생존, 작업 완료·계속되는 로그·메모리 회수

제출 실행은 [manifest.json](../evidence/manifest.json)으로 고정했다. 초기 CPU 10% 탐색과 0.5초 CPU 관측은 `exploratory_runs`로 기록하고 최종 비교 수치에서 제외했다. 탐색 결과도 작업 폴더에는 보존한다. 제출 ZIP에는 최종 6회의 원문을 포함한다.

## 수집 도구: 테스트 11개 통과

[테스트 원문](../evidence/tool-tests.txt)은 `bash tests/test_monitor.sh`로 재현한다.

- 숫자 범위·bool 형식, NaN/무한대/비양수 관찰 시간 거부
- `/proc` PID·그룹 읽기, PID 재사용 시 CPU 측정 구간 초기화
- root·없는 바이너리·포트 점유 사전 검사
- 실제 임시 프로세스의 RSS 증가와 CPU 부하 기록
- 자체 SIGTERM과 관찰 만료 구분, 명시적 flush 없는 종료 직전 문구 보존
- 부모 종료 후에도 자식 추적·정리
- Ctrl+C 시 결과 보존과 정리, 기존 증거 덮어쓰기 거부

fixture 테스트는 `/tmp`의 제한된 부하로 실행하며 실습 앱을 대체하지 않는다. 고정 포트 preflight는 mock하고, 실제 15034 바인딩은 제공 앱의 6회 실행에서 별도로 확인했다.

## 계측과 해석의 한계

CPU는 `/proc`의 user+system 틱을 실제 경과 시간으로 나눈 구간 값이며 논리 CPU 하나가 100%다. `ps %CPU`의 수명 평균, 앱 `Current Load`, 전체 CPU 평균을 구분한다. 0.1초 관측에서도 틱 단위 양자화와 샘플 타이밍 영향을 받는다. RSS는 근사값이며 강제 종료 직전 할당을 놓칠 수 있다.

OOM은 앱 MemoryGuard 종료이고 커널 OOM을 입증한 것이 아니다. Deadlock은 실제 락 보유·대기 로그와 정체로 추론했으며 내부 소스는 분석하지 않았다. `MULTI_THREAD_ENABLE=false`여도 정상 메모리·CPU 워커 등 OS 스레드가 여러 개 존재한다. 이 설정은 앱의 문제 있는 동시 트랜잭션 시나리오를 회피한 것으로 해석한다.

After의 90초 생존은 관찰 상한까지의 결과이며 영구적인 안정성을 보장하지 않는다. 6개 실험을 사용자·네트워크 네임스페이스에서 실행했지만 CPU와 메모리는 호스트 자원을 사용했다. 기존 서비스·네트워크 설정은 변경하지 않았다.
