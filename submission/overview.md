# Linux 장애 분석 과제 2 수행 보고서

AI/SW Basic · Linux와 OS · 2026-09-18

교육기관 제공 `agent-app-leak.zip`의 Linux x86 실행 파일로 OOM Crash, CPU Latency, Deadlock을 재현했다. 각 사례는 발생 현상, 원문 로그·관제 증거, 원인 분석, 환경변수 변경 전후 검증의 네 항목으로 작성했다. 보너스 스케줄링 분석과 공통 Issue 템플릿을 덧붙였다.

## 주요 결과

| 사례 | 변경 | 관측 결과 |
| --- | --- | --- |
| OOM | MEMORY_LIMIT 64 → 128 MB | MemoryGuard 종료까지 8.418 → 17.536초, 약 2.08배 생존 |

| 보너스 | 정상 시나리오 작업 로그 | A→B→C 교대·진행률 재개: 앱 수준 Round-Robin 패턴 |

## 실행 환경과 증거

WSL2 Linux 6.6.87.2, x86_64, 논리 CPU 12개, 일반 계정 kjw(UID 1000). 사용자·네트워크 네임스페이스를 분리해 기존 서비스와 충돌 없이 `0.0.0.0:15034`에 바인딩했다. CPU·메모리는 호스트와 공유한다. 실제 앱의 부팅 검사 6단계가 모두 통과했다.

앱 원본 SHA256:

```text
7e0a19cfa80ece6b547a5008273661f0d4d71e526e96b51e0d0f341dd1bb3e40
```

OOM·Deadlock은 0.5초, CPU는 0.1초 간격으로 관측했다. 각 비교 쌍에서는 변수 하나만 바꾸고 90초 관찰 상한을 동일하게 적용했다. 앱 로그 시각은 KST(UTC+9), CSV와 수집기 로그는 UTC다. 그래프는 정확한 소켓 소유 워커의 CSV에서 생성했다.

수집기 테스트 **11개**, 실제 원본·부팅·비교 조건·장애 증거 검사 **50개**가 통과했다. 실행 명령과 증거 경로는 `evidence/manifest.json`, 계산 결과는 `evidence/comparison.json`에 있다.

## 첨부 자료 안내

이 PDF에는 `source-and-evidence.zip`을 첨부했다. 첨부를 지원하는 PDF 뷰어에서 원본 CSV·로그·ps/top 출력·수집 코드와 SHA256 목록을 열 수 있다. 같은 ZIP을 PDF 옆에도 별도로 제공한다. 교육기관 제공 바이너리와 실행용 키 파일은 ZIP에 넣지 않았다. 보고서의 상대 링크는 함께 제공한 폴더 구조에서 사용할 수 있다.

## 결과 해석의 범위

메모리 상한 증가는 누수 자체의 근본 해결이 아니고, 90초 생존은 장기간 안정성 보장이 아니다. OOM은 앱 MemoryGuard 종료로 확인했으며 커널 OOM으로 단정하지 않았다. 앱 내부 Current Load와 OS CPU를 구분했고, 실제 사용자 요청 지연은 측정하지 않았다. 모든 분석은 원본 앱 실행 로그와 Linux 관제 결과를 사용했으며 바이너리 역공학은 수행하지 않았다.
